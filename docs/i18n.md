# Localization

## Runtime and source of truth

Use **Android resources in the APK and Polygo in CI**. No persistent translation
service, runtime translator, network permission, language enum or model in the
APK. English and the eight catalogs below are bundled. Building or using them
does not need an inference model. Optional Ollama regeneration still requires
explicit runtime/model pins; it is not part of an ordinary build.

- English: `res/values/strings.xml`. Accepted translations: ordinary
  `res/values-<qualifier>/strings.xml`. Keep `polygo.lock` with the XML so source
  tracking survives fresh runners. `glossary.toml` holds repeated terminology;
  complete-message corrections belong in the locale XML.
- `polygo.toml` selects generation targets as BCP-47 tags, not an application
  language allowlist. `{android_locale}` maps `pt-BR` to `values-pt-rBR` and
  `zh-Hant` to `values-b+zh+Hant`. Add only real translations, not English copies.
- AGP discovers catalogs and generates LocaleConfig. Dependency-only translations
  do not advertise app languages. Android selects plural forms and English
  fallback; Settings → App language opens Android's per-app language settings.
- RTL uses start/end layout. Bidi isolation is display-only: names, IDs, shortcut
  formats and pinned labels are never rewritten. Reboot state localizes on read;
  historical reports, shell output and technical errors stay verbatim.

XML remains portable if the CLI or model is replaced. One sideloadable APK holds
all accepted catalogs; language split APKs are optional distribution, not model
execution. No model promises universal coverage or proves that a deletion warning
means the right thing. A maintainer owns acceptance; volunteer translators are
not required to generate the first draft.

## First translation batch

English (`en`) remains the source, not a translation target. The selected batch is:

```toml
target_locales = ["zh-Hans", "zh-Hant", "es", "hi", "bn", "ru", "ja", "tr"]
```

This covers Simplified Chinese, Traditional Chinese, Spanish, Hindi, Bengali,
Russian, Japanese and Turkish. **Portuguese and Western Punjabi are deferred.**
Chinese scripts have separate catalogs (`values-b+zh+Hans` and
`values-b+zh+Hant`), not a single generic Chinese file.

These are real, complete catalogs, enabled in `polygo.toml` and included in the
generated Android language list. Commit locale XML and `polygo.lock` together.
Do not add placeholder English copies or weaken completeness/format gates.

### Initial translation provenance and review limits

The first batch was written directly by an AI coding assistant on 2026-11-03,
using the session's configured model alias **`gpt-6-astra`**. This alias is not an
immutable model snapshot, and no reproducible Ollama inference run is claimed.
No separate model was downloaded and no hosted translation API was provisioned.
The assistant checked the text against the English source, including all-data
deletion scope, unaffected users, disable versus stop versus background limits,
placeholder ordering and separate Chinese terminology. **Independent fluent-
speaker review and device-language acceptance are still outstanding.** Corrections
are welcome; structural checks do not certify translation quality.

The initial v2 lock uses `provider = "ai-editor"` and `model = "gpt-6-astra"`,
not `human` or `ollama`. It was initialized from the actual XML with the reviewed
Polygo library's `project::load_units` and `Lock::record` APIs; each applicable
locale unit records its source hash, translated-text hash and timestamp. All
1,672 values have records, so source changes become stale and later XML corrections
remain protected. Do not reinitialize the lock to accept subsequent source changes.
Android lint requires Spanish's `many` quantity for millions. The pinned CLI
checks these eight extra values but omits them from its status counts (1,664).
For these integer-count messages, `many` intentionally equals `other`; catalog
tests require their text and source/translation hashes to remain paired. This
prevents a stale `many` from slipping through after an `other` update. Keep that
guard until the CLI tracks the additional CLDR category itself.

The configured `length_ratio = 4.0` keeps Polygo's heuristic bounded while allowing
compact Chinese text. English character counts are not a measure of Chinese
meaning. No structural check is disabled; a regression confirms that a truncated
Chinese deletion warning still fails strict checks. Spanish `%1$d clones` is
intentionally identical to English and recorded with the other translated units.
The product-name/version template is non-translatable, like the product name.

## GitHub Actions

`.github/workflows/translations.yml` is shared by the normal Android build and
signed release. Those callers **only validate**, without starting a model or
receiving release secrets. Missing, stale or quarantined translations block them.
Human-edited text is protected and reported as edited, not silently regenerated.

Run **Translations → Run workflow** to generate a separate, unsigned draft patch.
The `generate` checkbox defaults on for that manual run and off for reusable calls;
turn it off for checks only. `retry_review` defaults off; select it explicitly to
retry quarantined machine results. There is no scheduled generation, automatic
commit, PR, protected-branch write or automatic acceptance. This artifact-only
policy keeps the workflow usable with any reviewed source/contribution process.

### One-time configuration

1. Select a reviewed Polygo implementation with lockfile v2/per-locale tracking
   **and** correct Android inline XML attributes/namespaces. Upstream 0.1.9 without
   those fixes is insufficient. Set repository Actions variables:

   | Variable | Required value |
   | --- | --- |
   | `POLYGO_REPOSITORY` | Public CLI source repository, `owner/repo` |
   | `POLYGO_REVISION` | Full **published** 40-hex commit containing the fixes; never `main`, `latest` or an unpublished local commit |
   | `OLLAMA_IMAGE` | `ollama/ollama@sha256:<reviewed image digest>`; generation only |
   | `OLLAMA_MODEL_DIGEST` | Exact downloaded model digest (optional `sha256:` prefix); generation only |

   The workflow builds that exact checkout with Rust 1.99.1 and
   `cargo build --release --locked`. It does not download an unchecked latest CLI
   or vendor its source into this app. CLI source is checked out beside the app
   on the runner, not inside its build inputs. No API credentials are required.

2. In a review branch, select any additional `target_locales` and set
   `[provider].model = "model:tag"` in `polygo.toml`. The first batch is already
   enabled; only the optional generation model remains unset. Review its license,
   language/script coverage, RAM, download size, runner time/cost and destructive
   warning quality before selecting it; open weights alone do not mean an
   open-source license. The prepared runner is `ubuntu-latest`, **CPU-only**, with
   a 90-minute job limit. Larger models may need a separately reviewed runner.

3. Dispatch the workflow on that branch. It starts a disposable, digest-pinned
   Ollama container bound to loopback, explicitly pulls the configured model,
   verifies its digest before inference and removes the container afterward.
   Registry downloads still use the network. Only catalog text/comments and the
   glossary enter prompts: code context and cross-project memory are disabled.
   There is no hosted API fallback or durable inference service/model store.

4. On success, download `translation-drafts-review-required`. It includes a
   `translations.patch`, coverage/status and source/CLI/model/runtime provenance.
   Apply to the matching source revision with `git apply --check` then `git apply`
   (or your normal patch review tool). Commit the accepted XML **and** lockfile
   with the configuration change through your normal review process. The artifact
   expires after 14 days and is not the durable source of translations.

The generation job runs strict Polygo checks, independent XML parsing, package
checks, release/debug unit tests, Android lint and an unsigned APK build **before**
uploading the patch. Any failure, including quarantine exit code 3, fails the job;
no successful draft artifact is uploaded. Resolve/retry the failure locally or
in a new run rather than weakening checks. The artifact is still **unreviewed**:
structural validity is not semantic approval. Record the accepted language's AI
provenance/review policy in the change description; use independent model review
or fluent feedback where needed, especially for data loss and scope warnings.

Bundled targets require the public CLI repository/revision variables even for
check-only builds; missing pins/catalogs fail closed. The CLI fixture and strict
status checks run without inference. Model/runtime variables are required only
for explicit generation. Repository variables are operational pins; changes to
them require maintainer review too.

## Incremental updates and corrections

Normal translation touches new or source-changed machine translations only.
Editing locale XML protects that text from overwrites; `polygo review` can handle
quarantined suggestions locally. Never delete the lockfile as a routine retry.
Legacy v1 locks require an explicit migration decision; a fresh project starts
with v2. A failed/partial locale update must leave other locales stale.

**Protected corrections still need source-change review:** Polygo reports edited
text as edited even if English changes. Passing the status gate does not establish
that a human correction is still faithful. Review affected corrected sentences
alongside source changes; do not reset their hashes to force an overwrite.

Use glossary locale tables for recurring terms, not whole sentences. A *profile*
is an Android user container; a *clone app* is one installed instance. Disable,
force-stop, stop profile and restrict background activity have different effects.
Keep ALL-data deletion scope and unaffected users explicit. Non-translatable
`DELETE` is not a glossary entry: glossary matching is case-insensitive and would
also constrain the ordinary verb “delete”.

## Authoring and checks

- Stable semantic keys, whole sentences, indexed `%1$s`/`%2$d` arguments and
  Android plurals. Include the target locale's required quantities; do not build
  translated sentences by concatenating words.
- Preserve `xliff:g`, XML namespaces, inline markup, URLs, Android API identifiers
  and `{id}`, `{name}`, `{clone}`. Use Android escaping (`\'`, `\n`, XML entities).
- Never translate `translatable="false"` resources, names, IDs, or the exact
  confirmation token. UI uses `getString`/`getQuantityString`; no alternate loader.
- `polygo check --strict --no-baseline` checks formats and glossary. The status
  gate checks **all** configured locales, including new/stale/untranslated/review
  counts; no warning-only or selected-locale shortcut to release acceptance.

From the app root (Python 3.11+, plus SDK/JDK setup in the README):

```sh
python3 tools/check_i18n.py
python3 -m unittest discover -s tests/i18n_tests -v
# Optional real CLI transport/writer regression; no model inference:
POLYGO_BIN=/path/to/pinned/polygo python3 -m unittest discover -s tests/i18n_tests -v
polygo check --strict --no-baseline
polygo status --json > "$HOME/.cache/appclone-status.json"
python3 tools/check_i18n.py --status "$HOME/.cache/appclone-status.json"
python3 tests/check_package.py
python3 -m unittest discover -s tests/build_tests -v
python3 build.py --self-check
python3 build.py --lint
python3 build.py
```

The CLI fixture runs the actual catalog through a loopback Ollama-protocol test
double, including multiline arguments, XLIFF, Russian/Arabic/Chinese plural shapes,
selective source updates and hand edits. Its marked English text never enters
production; it proves transport/writer behavior, not translation quality.

Debug-only Android pseudolocales `en-XA`/`ar-XB` exercise expanded text, RTL,
accessibility, plural lookup, exact tokens, verbatim names and locale discovery.
Native lint makes missing/extra translations, format errors and missing plural
categories fatal. Test real language switching, recreation, long names, large
fonts, landscape and TalkBack on a device before release. Host tests do not prove
OEM Settings behavior, semantic fidelity or performance on real devices.
